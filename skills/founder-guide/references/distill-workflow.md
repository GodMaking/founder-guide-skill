# 蒸馏工作流细则

本细则由 47 本批量蒸馏实践（小米创业思考 → 埃隆之书）固化，逐章写作时按此执行。

## 一、源书解析

| 源类型 | 做法 | 失败处理 |
|---|---|---|
| PDF | `pdfinfo` 看页数与文本层 → `pdftotext -layout book.pdf full_text.txt` | 扫描版（无文本层）才 OCR；仍失败则报告缺源 |
| 飞书/豆包文档/书单 | `lark-cli docs +fetch --doc <URL> --doc-format markdown`；书单条目内 PDF 素材 token 用 `docs +media-preview <token> --output book.pdf`（`+media-download` 403 为死路，勿用） | 权限不足时提示用户授权 |
| 网页 | 抓取正文全文落盘 | 动态页尝试浏览器能力 |

全文落盘 `full_text.txt` 后，通读并记下：全书主线、可拆章节/主题块、关键原句、专有名词清单（角色名、墙语、术语、案例人物）。这些是成稿取材的唯一来源。

## 二、四件套规划

### requirement-checklist.json

固定五条需求骨架，按当前书改写：

- R1 交付形态：约3万字中文成书 Markdown + 原书 PDF，按用户要求上传云盘并交付链接
- R2 忠实转述：保留原书核心内容、关键原句、角色/专有名词，不虚构不发挥
- R3 字数契约：全书目标 N 字（默认 31040），tolerancePercent 10
- R4 去 AI 味：正文自然、具体，少连接词/模板句
- R5 交付：本地 final.md + book.pdf，避免重复上传

### outline.md 必需章节

```
# 全书大纲：<书名>（蒸馏成书）
## 核心主张      —— 一段话讲清全书要传达什么、成书将如何组织
## 目标读者      —— 谁在读、带着什么任务读
## 语气          —— 平实/温暖/具体，保留原书表达气质
## 章节规划      —— 表格：章节 | 标题 | 核心问题 | 用户收获 | 目标字数
## 章节依赖关系  —— 表格：章节 | 前置章节（保证叙事顺序）
## 总字数目标    —— 全书目标 + 分章分配 + 上下限
```

章数选择：一般 12–20 章；薄书（寓言/工具书）12–16 章，厚书（传记/大部头）16–20 章。每章目标字数 = 全书目标 ÷ 章数（取整，末章补差，合计必须等于全书目标）。

### chapter-ledger.md

表格：章节 | 标题 | 目标字数 | 当前字数。成稿后用脚本或人工回填当前字数（非空白字符）。

## 三、逐章成稿规范

1. **章标题**：`# 第X章`（汉字数字：第一章、第二章…），随后 `## 一、…` 二级标题、`### （一）…` 三级标题；不跳级，标题内不加粗，不用阿拉伯数字编号（`1.`、`1.1` 禁用）。
2. **每章结构**：二级标题 4–8 个，每个标题下 1–3 个自然段；单一小节也可直接落自然段。避免"连续编号条目代替正文"（≥3 个连续编号项而无论述会判违例）。
3. **忠实转述**：用原文事实/案例/原句组织，保留关键原句（可引用）、角色名、专有名词；需要解释时用转述口吻，不添加原书没有的观点与案例。
4. **去 AI 味**：
   - 段落首句避免"近年来/随着…发展/在当今社会/众所周知/综上所述/首先其次最后"
   - 一段内不堆 2 个以上连接词；不用"需要注意的是/值得关注的是"式套话
   - 少分号长句，少排比模板句；用具体事实、数字、人物动作推进
   - 不用"赋能/闭环/抓手"等黑话；不整段加粗；不加粗小标题连续堆叠（之间必须有正文）
5. **每章字数**：非空白字符尽量贴近目标字数（±15% 内可接受，全书合计必须落 ±10%）。
6. **合并 final.md**：`<!-- title: final -->` 开头 + 分章注释 `<!-- source: manuscript/chNN-….md -->` + 章节正文依次合并；不额外加封面页。

## 四、校验门槛（与 SKILL.md 一致）

见 SKILL.md「校验门槛」，全部通过才交付。校验脚本：`scripts/distill_check.py <工作目录>`。

## 五、交付

- 本地：`NN-书名/` 完整工作目录 + `deliverables/final.md` + `book.pdf`
- 云盘（用户要求时）：`lark-cli drive +upload --file <path> --name <名>` 上传 Drive 根目录，`+inspect` 核验，交付链接
- 回复：极简，≤300 字 / ≤8 行，给产物名、路径/链接、校验结果，提示下一本
