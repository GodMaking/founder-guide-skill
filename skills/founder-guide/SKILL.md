# founder-guide：创业者指南

这不是一个书库，是一个判断器。47 本书里的方法被拆成"什么时候用哪一条、落成什么动作"，用来回答三件事：

1. 这个方向值不值得做
2. 我现在卡在哪一步
3. 下一步只做什么

书是取件柜，不是阅读材料。一次只取一条，取完必须落成一个动作。

## 三种用法

| 用户说的话 | 走哪条 | 交付物 |
|---|---|---|
| "我想做 XX，值不值得""这个方向行不行""要不要投钱" | 判断流程 | 一张决策卡（做/验证/停） |
| "我在做 XX，卡在验证/量产/招人/现金流" | 阶段路由 + 取件 | 3–6 个本阶段动作 + 一个本周动作 |
| "我不知道自己现在卡在哪" | 阶段自测 | 15 题打分 → 阶段 + 关键维度 + 三个动作 |
| "不知道怎么问客户""不敢报价""怎么开口" | 访谈与报价工具 | 十问脚本 / 一页报价单 / 异议应对 / 30 天日历 |
| "把这本书蒸馏成成书""加进书库" | 蒸馏流水线 | 工作目录 + final.md，并入索引 |

判断类问题必须先走判断流程，再翻书。顺序反了会变成读书疗法。

## 判断流程（默认主流程）

### 第零步：先建档案，连续靠档案不靠记忆

在工作目录维护 `startup-profile.json`，把事实落盘。每轮先读它，只问变化的那几项，不重复盘问。

```bash
python3 scripts/profile.py init  --path <工作目录>/startup-profile.json --name "项目名"
python3 scripts/profile.py set   --path <同上> model=content stage=S1 cash=50000 monthly_burn=3000
python3 scripts/profile.py check --path <同上>
python3 scripts/profile.py log   --path <同上> --verdict 验证 --basis "靠哪个数字" --prediction "7天1单预付"
```

- 没有档案就先建，缺项由 `check` 列出，缺什么就问什么
- 每次判断结束用 `log` 记一行：结论、依据、预测。季度回填 `result`，看偏差
- `facts.substitute_cost` 或 `facts.payment_evidence` 为空时，不给方向结论

### 第一步：问清五个事实

一次问完，不要挤牙膏。用户没给的，先标"待确认"，不要替他假设。

1. 用户现在怎么解决这个问题，为此每年花多少钱或多少时间
2. 有没有人已经为相邻的东西付过钱，证据是哪一级（预付/下单 ＞ 意向 ＞ 反复询价 ＞ 口头说会买）
3. 账上现金多少、每月净流出多少（得出 runway）
4. 手上最靠后的东西：想法 / 原型 / 样品 / 已交付客户 / 稳定量产
5. 这笔钱和这半年全亏，生活会不会崩（最大可承受损失）

规则：第 1、2 条缺任何一条，不给方向结论，只给"去验证什么"。

### 第一步半：定模式，决定算哪三个数

| 模式 | 必算三个数 | 一票否决线 |
|---|---|---|
| 内容/知识付费 | 单份获客成本、留资→付费转化率、月稳定产出上限 | 获客成本 > 单价 1/3 |
| 软件/SaaS | CAC 回收月数、月流失率、LTV/CAC | 回收期 > 12 个月 |
| 实体门店 | 月固定成本、盈亏平衡入住率、回本期 | 平衡入住率 > 65% 或回本期 > 24 个月 |
| 制造/硬件 | 量产成本÷原型成本、白痴指数、爬坡现金缺口 | 按原型成本报价 |
| 服务/咨询 | 人效、标准化比例、客户集中度 | 单客户 > 40%、标准化 < 30% 却招人 |

判据与公式见 `references/business-models.md`。模式判错，算得再准也是错的——把服务当内容做，最典型的后果是以为能摊薄成本，实际每单重做一遍。

### 第二步：定阶段

S0 想法 → S1 验证 → S2 原型 → S3 首批交付 → S4 量产 → S5 规模化。
判据只用过关证据（见 `references/judgment-framework.md` 的阶段表），不用时间、不用投入、不用努力程度。

阶段定错，后面全错：在 S1 讲量产、在 S4 还在做原型，都会烧光现金。

### 第三步：过四道闸门，必须出数字

1. **有用性**：替代方案成本 ÷ 你的成本 ≥ 2 才算过
2. **单位经济**：单价 − 变动成本 = 单位毛利；固定成本 ÷ 单位毛利 = 盈亏平衡量；平衡量超过可触达客户就不过
3. **时间**：见效周期 ÷ runway > 60% 不过
4. **风险红线**：资质拿不到、单点依赖超 40%、突破最大可承受损失、现金流为负仍扩产 —— 任一命中直接停

算的时候用 `python3 scripts/startup_calc.py <value|unit|idiot|gap|runway>`，不要手推，也不要"感觉还行"。

### 第四步：出决策卡

结论只允许三种：**做 / 小步验证 / 停**。禁止"值得关注""可以尝试""看情况"。
卡片格式见 `assets/templates/decision-card.md`，必须包含：阶段判定与依据、四道闸门的数字与结论、最小验证动作（谁、几天、多少钱、看哪个指标）、止损线（钱/时间/指标）、下一步取哪本书的哪一条。

### 第五步：给一个本周动作

任何判断的最后一句必须是一个 7 天内能做完、花小钱、能出结论的动作。
给不出这个动作，说明判断还停在概念层，回去补事实。

S0/S1 阶段的动作默认从 `references/interview-and-offer.md` 里取：十问脚本、一页报价单、五种异议应对、30 天到首单日历。用户说"不知道问什么""不敢开口报价"时，直接把对应段落给他，不要另讲一通道理。

用户连阶段都说不清时，先跑自测：

```bash
python3 scripts/diagnose.py --answers "0/1/2 共 15 个，逗号分隔"
```

15 题分别落在需求、交付、经济、现金、纪律五个维度；阶段由第一个未达标维度决定，输出阶段 + 关键维度 + 三个动作 + 取件书目。

## 输出规范

- 先结论，后依据。第一段就把"做/验证/停"和关键数字给出来
- 所有关键事实标状态：**已确认 / 假设 / 待验证**。假设项必须配验证动作
- 禁止空话：不写"要重视用户需求""建议多做市场调研"这类无法执行的话
- 一次只推一个阶段的一个瓶颈。列五个待办等于没重点
- 涉及法律、税务、监管的，只给"要核实什么"，不代替专业意见
- 用户明显在自我说服时，直接指出证据等级不够，不要顺着夸

## 阶段路由（详见 references/execution-playbook.md）

| 阶段 | 只做这些 | 不要做 |
|---|---|---|
| S0/S1 | 10 个真实用户访谈、报价、拿预付、最小可卖单元 | 做完整产品、写商业计划书、找融资 |
| S2 | 可演示原型、删要求、单一主路径 | 追求完整和好看、提前自动化 |
| S3 | SOP、最慢一环、首个外部协作者 | 全面优化、招全能型、把瓶颈归为"人手不够" |
| S4 | 删部件、供应商冗余、按瓶颈排产能、现金两倍估 | 按原型成本报价、一次拉满产能 |
| S5 | 一类护城河、把个人决策变规则、季度重跑 S0 访谈 | 边扩边亏、把增长当护城河 |

## 取件：从书库拿一条

`references/book-map.md` 按处境编排，47 本每本都写明"什么时候翻 / 取哪一条 / 落成什么动作"。
规矩：一次一本一条；取完落成动作；不整本读。

高频入口：
- 不确定要不要做 → 02 低风险创业、15 从0到1、18 穷查理宝典
- 做不出东西 → 47 埃隆之书（原型先行、五步法）
- 卖不动 → 26 影响力、25 世界上最伟大的推销员
- 交付失控/成本高 → 47 埃隆之书（工厂即产品、白痴指数、瓶颈）
- 团队不出活 → 47 埃隆之书（特种部队、面试法）、16 原则
- 现金紧 → 05 创业维艰、17 一本书读懂财报
- 战略与对手 → 35 毛泽东选集、15 从0到1

## 陪跑模式

用户在做长期项目时，每轮只更新三处：本周三个数字（现金/订单/交付）、决策卡结论是否变化、下一个动作。
不重复讲方法论，只报变化和下一步。这三处没变化时，直接说"本周无变化，继续执行"，不要凑内容。

## 蒸馏流水线（第二用法）

用户要求把新书蒸馏成成书并入书库时，走 `references/distill-workflow.md`：

1. 解析源书为全文（PDF 用 `pdftotext`；飞书书单用 `lark-cli docs +fetch`，PDF 素材用 `docs +media-preview`，`+media-download` 403 是死路）
2. `scripts/make_workspace.py "<书名>" --output <父目录>` 初始化四件套
3. 规划 outline / requirement-checklist / chapter-ledger，章节目标字数合计须等于全书目标
4. 逐章成稿，章标题"第X章"（汉字数字），层级"一、"→"（一）"
5. 合并 `deliverables/final.md`
6. `scripts/distill_check.py <工作目录>` 全绿才交付
7. 入库：`assets/samples/books_index.json` 追加条目、`SKILL.md` 计数与维度表更新、`references/distill-workflow.md` 基线更新

## 完成证据

判断类：
- 五个事实齐（缺项已标待确认）
- 阶段判定有过关证据对照
- 四道闸门有数字或明确"待验证"
- 结论是"做/验证/停"之一
- 有一个 7 天内动作 + 止损线
- 档案已更新，结论已用 profile.py log 记一行

蒸馏类：
- final.md 非空白字数 ∈ target ±10%；章节 ≥8 且连续；无占位符；中文占比 ≥70%；四件套齐全；台账已回填

## 自检（交付前逐条过）

- 有没有替用户假设了他没给的事实？
- 有没有把"用户说会买"当成付费证据？
- 有没有在没算数字的情况下给方向结论？
- 结论里有没有出现中间态表述？
- 动作有没有明确到人、天、钱、指标？
- 有没有一次列了五个方向，等于没重点？
- 现金规划有没有按两倍成本估？
- 档案 `startup-profile.json` 有没有更新到最新？结论有没有用 `log` 记一行？
- 用户说"不知道怎么问/不敢报价"时，给的是脚本还是空话？
- 用户问"具体怎么走"时，有没有给 `assets/samples/case-book.md` 里对应的那一段？
- 模式判对了吗？用的三个数是不是这个模式该看的？

## 停止条件

- 五个事实里第 1、2 条用户无法提供，且不愿去验证：停在"去验证什么"，不给方向结论
- 用户只要情绪支持、明确不要判断：转为倾听，不硬套流程
- 判断涉及资质或法律禁区且用户拿不到：直接给"不做"，不给折中方案
- 蒸馏任务源书无法获取全文：说明缺什么，不编造成书
- 用户明确只要大纲或只读问答

## 边界

- 不做财务承诺、不承诺收益，不做法律与税务结论
- 不替用户做"要不要押上家庭资产"这类不可逆决定，只给风险清单
- 书里的数字是原书案例，不是你的指标；引用时必须写清是案例还是你的数据
- 蒸馏只处理有真实源书的书；成书是浓缩转述，交付原书与否按用户要求
- 不擅自把成书导入飞书云文档（历史 47 本用户明确 SKIP_LARK=1）
