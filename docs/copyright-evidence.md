# 权属证据整理方法

本文用于准备版权投诉、平台申诉或诉讼时的**权属证据**。目标不是“证明别人一定侵权”，而是把“这个作品由谁在什么时间创作、有哪些具体表达”整理成可核验的材料。

> 本文不构成法律意见。金额较大、反复侵权或跨平台销售时，建议咨询律师。

## 1. 先固定权属基础

至少保存以下材料：

| 材料 | 作用 | 从哪里取 |
|---|---|---|
| 仓库地址与首次提交 | 证明创作时间与公开时间 | `git log --reverse`、GitHub Commits 页面 |
| 每个版本的提交哈希 | 证明某个版本确实存在 | `git log --format='%H %ad %s' --date=iso` |
| LICENSE 与 Required Notice | 证明授权边界与署名 | `LICENSE`、`NOTICE` |
| README、SKILL.md、references、scripts | 证明具体表达 | 仓库文件 |
| 版本记录 | 证明持续创作与演进 | `CHANGELOG.md`、Git tags、Releases |
| 作者身份材料 | 证明你就是权利人 | GitHub 账号、邮箱、实名信息（仅私下提交） |

不要只保存“最新版”。侵权对比往往需要证明**对方抄的是哪一版**，所以每个重要版本都要留档。

## 2. 建立版本记录

推荐做法：

1. 每个重要版本打一个 Git tag，例如 `v1.2.0`
2. 在 GitHub 创建 Release，写清日期、变更内容与对应提交
3. 在 `CHANGELOG.md` 记录版本号、日期、主要变更
4. 对每个 Release 下载一份 zip 快照，保存 SHA-256
5. 把快照、哈希、截图放在独立备份目录，不放进公开仓库

生成文件哈希：

```bash
# macOS / Linux
shasum -a 256 founder-guide-skill-v1.2.0.zip

# Windows PowerShell
Get-FileHash .\founder-guide-skill-v1.2.0.zip -Algorithm SHA256
```

记录格式示例：

```text
版本：v1.2.0
日期：2026-11-13
提交：<git commit hash>
快照：founder-guide-skill-v1.2.0.zip
SHA-256：<hash>
保存位置：<本地备份路径 / 云盘只读目录>
```

## 3. 版权声明放在哪里

建议同时保留以下位置，形成互相印证：

- 仓库根目录 `LICENSE`：PolyForm Noncommercial 1.0.0 全文与 `Required Notice`
- 仓库根目录 `NOTICE`：版权声明、仓库地址、商业授权提示
- `README.md`：许可与商业授权章节
- `SKILL.md`：许可与商业使用说明
- 授权书与交付物版权页：授权编号、被授权人、授权范围

如果需要在代码文件加版权头，保持简短，不要影响脚本运行，例如：

```python
# Copyright 2026 GodMaking
# Licensed under the PolyForm Noncommercial License 1.0.0.
# Commercial use requires a separate written license.
```

不是每个文件都必须加；关键是仓库级声明一致、可追溯。

## 4. 创作时间证据

可用的时间证据，按获取难度排序：

| 证据 | 说明 | 注意 |
|---|---|---|
| Git 提交历史 | 每个提交有哈希、作者、时间 | 本地时间可改，GitHub 提交时间更可信 |
| GitHub Release / tag | 公开时间线 | 截图时带上 URL 与时间 |
| 公开文章/视频/课程发布记录 | 证明更早公开 | 保存原始链接与平台时间 |
| 软件著作权登记 | 官方登记证书 | 需要申请周期与费用 |
| 可信时间戳 | 第三方时间戳服务 | 需要选择合规服务商 |
| 公证 | 公证处对网页/文件取证 | 成本较高，适合重大案件 |
| 邮件/聊天记录 | 证明创作与交付过程 | 注意隐私与完整性 |

**不要伪造时间**。平台和法院会看多条证据是否互相印证，单一截图很容易被质疑。

## 5. 证据保全怎么做

### 网页证据

- 截图要包含完整 URL、页面标题、卖家昵称、价格、销量、发布时间
- 同时保存网页 PDF 或 `wget`/浏览器“另存为”结果
- 录屏从打开链接到展示商品详情，中间不要剪辑
- 记录取证时间、设备、网络环境

### 文件证据

- 保存原始文件，不要只保存转发后的副本
- 计算 SHA-256，记录文件大小与修改时间
- 对疑似盗版文件，保留下载链接、下载时间、订单号、付款记录
- 不要修改疑似侵权文件；如需对比，复制一份再操作

### 对比证据

- 使用 `diff`、文件哈希、相似度工具做初步对比
- 把“完全相同”“高度相似”“仅功能相似”分开列
- 对每一处相似，标注原文件路径、行号/章节、对方文件路径、行号/章节
- 截图时同时展示两侧内容，避免只截对方

## 6. 侵权取证的基本流程

1. **发现**：记录商品链接、平台、卖家昵称、价格、销量、发布时间
2. **初判**：对方是商业销售，还是非商业分享？是否保留 LICENSE 与署名？
3. **购买测试**（如安全且必要）：保留订单、付款、交付文件、聊天记录
4. **对比**：按 [侵权对比清单](infringement-checklist.md) 逐项比对
5. **固定**：截图、录屏、文件哈希、网页 PDF、下载文件
6. **投诉**：按 [平台投诉模板](takedown-templates.md) 提交
7. **记录**：保存投诉编号、平台回复、处理结果、时间线

不要为了取证去诱导对方、伪造聊天记录或恶意下单。取证手段本身也要合法。

## 8. 隐私与合法边界

- 不要在公开材料中披露买家的真实姓名、电话、地址、身份证、支付账号
- 如需证明“泄露来自某份授权”，可只提供授权编号、订单号后四位或哈希
- 不要人肉搜索、骚扰、威胁对方或其家人
- 不要伪造证据、PS 截图、篡改时间
- 不要虚构“100% 胜诉”“平台一定下架”
- 投诉材料只陈述可核实的事实

## 9. 许可证不能解决的部分

- 公开源码无法在技术上阻止复制
- 平台投诉是否受理、是否下架，由平台依据证据判断
- 独立开发类似功能不一定侵权
- 著作权保护具体表达，不保护思想、方法、概念
- 跨境、匿名、频繁换号的卖家，维权成本可能高于收益
- 软著登记、公证、诉讼都需要时间和费用

## 10. 最小行动清单

如果今天只做五件事：

1. 给当前版本打 tag，创建 Release
2. 下载 zip 快照，计算 SHA-256
3. 截图保存 GitHub 首次提交与当前版本提交页
4. 保存 LICENSE、NOTICE、README 许可章节截图
5. 建立一个只读的“维权证据”目录，按日期归档

完成这五件，后续发现侵权时就不会从零开始。
