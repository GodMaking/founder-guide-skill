# 闲鱼自动发货与交付方案

本方案的目标：买家下单后能**自动拿到公开资源与授权编号**，按教程自行安装并跑通一个真实案例；作者只处理授权书签发与必要答疑。

前提：**GitHub 上的源码、模板、案例、文档与付费交付内容一致**。付费不是解锁源码，而是购买商业授权、作者后期制作的中文安装使用教程，以及订单页约定范围内的版本更新/答疑。

## 1. 交付清单

| 交付项 | 免费公开 | 付费交付 | 说明 |
|---|---|---|---|
| 源码、模板、参考文档、脚本 | 是 | 是 | 同一份内容，不设付费墙 |
| README、快速开始、FAQ | 是 | 是 | 降低安装售后 |
| 案例与决策卡示范 | 是 | 是 | 数字为虚拟，只示范判断链 |
| 个人商业使用授权书 | 否 | 是 | 唯一编号，按订单签发 |
| 中文安装与使用教程 | 否 | 是 | 作者后期制作，按订单交付 |
| 版本更新提醒 | 是（仓库） | 按订单页 | 不承诺无限期 |
| 答疑 | 否 | 按订单页 | 不承诺无限量 |

## 2. 自动发货流程

```text
买家下单
  ↓
平台自动发货：发送「资源与编号消息」
  ├─ GitHub 仓库地址
  ├─ 安装教程链接（作者后期制作）
  ├─ 快速开始与 FAQ
  ├─ 一个已预生成的授权编号
  └─ 授权书信息登记说明
  ↓
买家提交：订单号 + 昵称 + 授权编号（不需要真实姓名）
  ↓
作者用 issue_license.py 签发具名授权书
  ↓
把授权书发给买家，并在本地台账登记
  ↓
买家按教程安装，跑通一个真实案例
```

### 为什么用预生成编号

平台自动发货时，买家还没提供昵称，无法当场生成具名授权书。做法是：

1. 先批量预生成编号，上传到平台自动发货库存
2. 买家收到编号后，再提交订单号 + 昵称
3. 作者用 `--code` 指定该编号，签发具名授权书

这样编号在发货时就能自动交付，授权书只需一次人工签发。

## 3. 预生成编号

```bash
# 生成 50 个编号，输出到 ./licenses/codes-YYYYMMDD.csv
python3 skills/founder-guide/scripts/issue_license.py --gen-codes 50 --output ./licenses
```

注意事项：

- 编号文件含未使用编号，不要提交公开仓库
- 文件已存在时脚本会拒绝覆盖，避免把未使用编号冲掉
- 编号中的日期是取号日期，不是授权日期
- 建议按批次记录：生成日期、数量、上传平台、已使用数量

## 4. 签发具名授权书

```bash
python3 skills/founder-guide/scripts/issue_license.py \
  --buyer "闲鱼昵称" \
  --order "订单号" \
  --code "FG-20261113-XXXXXXXX" \
  --product skill \
  --output ./licenses
```

如果买家买的是成书：

```bash
python3 skills/founder-guide/scripts/issue_license.py \
  --buyer "闲鱼昵称" \
  --order "订单号" \
  --code "FG-20261113-XXXXXXXX" \
  --product books \
  --books "01,47" \
  --output ./licenses
```

批量签发：

```bash
# CSV 表头：buyer,order,product,books,code
python3 skills/founder-guide/scripts/issue_license.py --batch buyers.csv --output ./licenses
```

签发后：

- 发送 `授权书-FG-....md`（或转成 PDF）
- 如需把版权页写进交付物，加 `--embed deliverables/final.md`
- 在本地台账核对编号、买家、订单、日期、范围
- 不要公开买家姓名、电话、地址、身份证

## 5. 买家信息最小化

只收集：

- 订单号（用于对账）
- 昵称（用于授权书抬头，可用化名）
- 授权编号（来自自动发货）
- 购买的产品类型

不收集：

- 身份证
- 住址
- 电话
- 支付账号
- 与交付无关的个人信息

告知买家：

> 授权书可使用昵称，不需要真实姓名。作者只在本机台账记录昵称、订单号、授权日期与授权范围，用于签发、核验与维权，不联网上传，不采集额外个人信息。

## 7. 中文安装使用教程（作者后期制作）

教程大纲见 [buyer-tutorial-outline.md](buyer-tutorial-outline.md)。建议交付形式：

- 一份图文 Markdown / PDF
- 一段 10–20 分钟录屏
- 一份可复制的命令清单
- 一份常见报错对照表

**教程尚未制作完成时，商品页不要写“含教程”，先卖授权或等教程完成后再上架。** 不要虚构交付物，也不要把公开 README 的快速开始说成付费教程。

教程不要求覆盖所有功能，但必须让买家完成：

1. 安装 Skill
2. 跑通 15 题阶段自测
3. 用 `startup_calc.py` 算一次闸门
4. 用真实项目跑一次判断，得到一张决策卡
5. 知道去哪里看许可、FAQ、版本记录

## 8. 售后与纠纷

- 安装问题：先让买家按 FAQ 自查，再让对方提供报错截图/命令输出
- 授权书信息错误：按订单号核对后重签，旧授权书标记作废
- 退款/退货：按闲鱼平台规则与商品页说明处理，不承诺平台之外的退款
- 盗版/倒卖：保存证据，按 [平台投诉模板](../docs/takedown-templates.md) 处理
- 买家转售：书面提醒，必要时终止授权并保留证据

## 9. 合规红线

- 不虚构独家源码、付费功能、安装成功率、创业盈利
- 不把公开仓库内容说成“只有付费才能拿到”
- 不承诺“买了就能赚钱”
- 不把原书内容说成自己原创
- 不声称购买 Skill 授权就获得原书版权
- 不公开买家个人信息
- 不使用“100% 下架”“ guaranteed”等绝对化承诺
